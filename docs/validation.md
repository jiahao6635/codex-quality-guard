# 验证范围

## 本地可重复检查

在仓库根目录执行：

```sh
node scripts/verify-scorer.mjs
node scripts/verify-ui.cjs
cargo test --manifest-path backend/Cargo.toml --locked
cargo fmt --manifest-path backend/Cargo.toml --all -- --check
cargo clippy --manifest-path backend/Cargo.toml --locked --all-targets -- -D warnings
bash -n scripts/package.sh scripts/tick.sh
```

上述验证不发真实模型请求，不需要生产账号、数据库或管理员凭据。首次获取 Cargo 依赖需要网络；评分校验本身只使用仓库内固定数据。

| 层级 | 核对内容 |
| --- | --- |
| 评分器 | 校验固定上游文件 SHA256；单题、双题、三题合成样本的 Rust/原版 JavaScript 聚合结果及全部候选概率一致，概率绝对误差小于 `1e-10`；核对完整文本解析、最少数字数量和无效输入拒绝 |
| 流输出解析 | 要求完整终态与纯文本输出；拒绝缺失终态、长度截断、错误及非文本/工具响应 |
| 纯状态机 | 三题聚合判定后准入、两轮异常隔离、轮次间隔、候选变化、unknown打断、两轮恢复、退避上限、时钟回拨和持久化重启 |
| 假宿主协议 | 启动实际插件子进程，通过 SDK 帧交换测试扩展页资源及路由注册与调用、维护、指定账号管理路由与 CLI、多个账号分页、自动轮巡和共享预算、空分组兼容读取与失败拒绝、租约/CAS冲突、Key范围拒绝、组变更失败、陈旧读回、隔离与恢复同步 |
| 打包 / CI | 固定 SDK 与打包 CLI 的提交；按目标构建插件包，CI上传 Linux x86_64 artifact |

假宿主的模型返回和分组事实是测试构造的数据。测试验证插件协议和状态转换，不能代替真实 OpenAI 输出质量或生产调度验证。测试数量以当次 Cargo 输出为准。

## 评分器能说明什么

使用 ModelTrace 固定版本的公开参考库。每份完整输出独立提取特征并计算各候选原始分数，三份分数取平均，再统一使用 `calibration["3"]` 做 softmax。不是平均三个概率，也不是将三个单题判定投票。单题、双题评分仅供离线一致性检查，线上整轮必须三份有效输出。原始参考数据的模型标签由上游项目提供，本项目没有独立认证其后端身份。

解析规则沿用上游：保留最长合法数字序列、顺序及重复值，不补齐也不裁成要求数量；至少需要 `max(80, ceil(要求数量 × 0.55))` 个1～355范围内整数。完整传输终态独立验证：即使部分输出数字够多，只要上游未完整结束也不能评分。

对照项目 [hlwy-ai-checker](https://github.com/hanlinwenyuan/hlwy-ai-checker) 使用重复单数字采样形成分布，采样协议不同。本插件采用 [ModelTrace](https://github.com/xqy2006/ModelTrace) 三次长整数挑战，不混用其参考分布。

当前 `0.99/0.01`、每轮3题、两轮异常与两轮恢复规则尚未使用本部署的独立真值集校准。它们表达行为证据强度，不能解释成“99%证明真实模型”，也不能推导某一次业务请求必然被降级。

不使用 `x-codex-safety-buffering-faster-model`、`enabled` 或 turn-state 长度作为判定依据。探针错误、超时、工具输出、截断或解析失败的尝试不参与聚合，每轮最多尝试六次。未收齐三份有效输出、整轮过期或低分差时无法判定，不作为降级证据。已冷却账号遇到整轮无法判定时保持隔离并退避。

## 真实部署验收尚未完成

旧版在 CPR 3.18.3 实机触发过一次自动探针，20秒超时后记录为 unknown，未取得可评分输出。本次三题聚合流程仍需真实推理验收；此前的页面可访问、插件已安装或协议测试通过都不能代替这一验证。网关实时调度缓存与业务 Key 的隔离路由仍待验证，状态中的 `runtime_isolation_verified=false` 保留这一边界。

部署后的验收至少要涵盖：

1. **准入与范围**：宿主资源维护创建两组两 Key；只有配置中的原生启用 OpenAI 账号进入探测组；自有与额外业务 Key 均只绑定健康组。
2. **三题与定向调用**：确认三次挑战固定同一配置账号、出口和目标模型，互不携带上下文；三份完整输出和请求 ID 可通过单账号 `POST evidence` 读回，全账号 `GET status` 仅含摘要；只有1/3或2/3时无新归因，3/3时与固定 JavaScript 实现重新计算一致。中断后可接续，超时及预算不足不伪造结果。确认没有别名或其他路由插件改写目标模型；通过宿主 API 固定账号不等于已验证实际后端身份。
3. **隔离传播**：用可控测试池形成隔离状态，先核组成员读回，再核新业务请求不再选择该账号；已经在途的请求单独记录。
4. **恢复门槛**：冷却到期不会直接回组；完整两轮恢复证据成立并经维护同步后，才重新收到业务流量。
5. **旁路和故障**：业务 Key 多绑组时停止探针；组写入/读回失败时明确报错；重启保持已冷却状态；原生手动禁用账号不会被插件启用。
6. **消耗和全池保护**：核对宿主实际 usage/账单、日预算停止状态、探针滞后与 `pool_guard`；它不是上游输出长度或费用的硬上限。

质量误报校准应使用独立、可说明来源的基线账号与数据，保持相同目标模型、推理强度和宿主路径，并按完整确认轮评估误隔离/误恢复率。不要用参与调参的样本同时声称独立验证准确率。

## 留存

插件状态保存每账号当前或最近一轮的挑战提示词、完整输出、请求 ID、解析数量和候选排序，以及最近12轮摘要、质量状态、租约和预算。开始新一轮会替换上一轮完整证据；超过30分钟的未完成轮次会失效。每份输出上限16 KiB（包括 JSON 转义后的大小），过大文本拒绝评分，不截断后继续。

扩展页默认加载全部账号摘要；完整提示词和输出由用户按账号点击加载，经 `POST evidence` 单独读取，避免全部账号的原始文本挤入一次管理响应。`POST probe` 仍返回本次账号的完整轮次证据。

本仓库黄金样本全部是合成数字，不包含此前真实测试输出。宿主可能按自己的配置记录探针请求，部署时应同时核对宿主日志留存。
