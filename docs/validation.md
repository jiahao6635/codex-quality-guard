# 验证范围

## 本地可重复检查

在仓库根目录执行：

```sh
node scripts/verify-scorer.mjs
node scripts/verify-ui.cjs
cargo test --manifest-path backend/Cargo.toml --locked
cargo fmt --manifest-path backend/Cargo.toml --all -- --check
cargo clippy --manifest-path backend/Cargo.toml --locked --all-targets -- -D warnings
bash -n scripts/package.sh scripts/tick.sh
```

上述验证不发真实模型请求，不需要生产账号、数据库或管理员凭据。首次获取 Cargo 依赖需要网络；评分校验本身只使用仓库内固定数据。

| 层级 | 核对内容 |
| --- | --- |
| 评分器 | 校验固定上游文件 SHA256；单题、双题、三题合成样本的 Rust/原版 JavaScript 聚合结果及全部候选概率一致，概率绝对误差小于 `1e-10`；核对完整文本解析、最少数字数量和无效输入拒绝 |
| 流输出解析 | 要求完整终态与纯文本输出；拒绝缺失终态、长度截断、错误及非文本/工具响应 |
| 纯状态机 | 三题聚合判定后准入、两轮异常隔离、轮次间隔、候选变化、unknown打断、两轮恢复、退避上限、时钟回拨和持久化重启 |
| 假宿主协议 | 启动实际插件子进程，通过 SDK 帧交换测试扩展页资源及路由注册与调用、维护、指定账号管理路由与 CLI、多个账号分页、自动轮巡和共享预算、空分组兼容读取与失败拒绝、租约/CAS冲突、Key范围拒绝、组变更失败、陈旧读回、隔离与恢复同步 |
| v0.5.0 可视化模式 | 固定账号与所选模型／推理强度、共用预算、独立证据读取、最近4份留存、错误输出拒绝、视觉测试不推进指纹或质量状态、共享租约阻止重叠调用 |
| 扩展页 | 三题指纹与鹈鹕模式、明确账户 ID、完整证据加载、模型选择、图片预览、HTML／JSON 复制导出；界面检查使用构造数据，不代表真实生成质量 |
| 打包 / CI | 固定 SDK 与打包 CLI 的提交；按目标构建插件包，CI上传 Linux x86_64 artifact |

假宿主的模型返回和分组事实是测试构造的数据。测试验证插件协议和状态转换，不能代替真实 OpenAI 输出质量或生产调度验证。测试数量以当次 Cargo 输出为准。

## v0.6.0 绘图与逻辑测试

鹈鹕提示词替换为用户指定原文，新增糖果逻辑测试，两项界面默认 `gpt-6-astra / medium`。糖果明确最终答案21通过，明确其他数字未通过；没有结论、矛盾结论、超时或请求失败无法判定。绘图通过人工标记判定，图像预览不执行生成的 JavaScript，静态预览本身不能证明动画失败。

验证覆盖固定账号／模型／强度、完整原文、保守答案提取、独立 `logic` 证据、人工判定保存、共享预算及租约。三题指纹与冷却状态不受两项手动测试影响。新增路由的假宿主与页面测试使用构造数据，不代表真实上游生成效果。

2026-10-01，v0.6.0 完成50项 Rust／假宿主测试、页面流程检查及20组合成评分对照，Linux CI通过。已通过 CPS 的 GitHub 更新入口升级到 CPR 3.18.3 实例，核对新增糖果入口、两项 `gpt-6-astra / medium` 默认值、完整提示词、旧鹈鹕原文读取和人工判定按钮。服务端升级前后配置、既有指纹及绘图证据、预算一致。当天额度已用8/7次，本版未追加真实模型调用；人工判定写入仅通过假宿主验证，未改写生产历史判定。

## v0.5.0 双模式边界

ModelTrace 继续使用同账号三份完整答案的原有评分协议。新增的鹈鹕模式通过 `POST visual` 固定账号、模型和推理强度，每次请求最多110秒并受宿主剩余期限限制；与 ModelTrace 共用预算和账号执行租约。它保存人工对比证据，不产生自动模型归因，不推进指纹轮次或改变账号冷却／恢复状态，自动维护也不调用鹈鹕模式。

页面参考 [Sub2API IQTestModal 固定版本](https://github.com/ranxi2001/sub2api/blob/2d55b424e3cac42814e81c9fec700595985faafb/frontend/src/components/admin/account/IQTestModal.vue) 的账户信息和输出卡片交互，自行实现，未复制源码。CPS 页面通过 SVG 图像模式预览 HTML／SVG／CSS；不执行模型脚本，不加载外部资源，不借子 iframe 或下载绕过宿主限制。导出弹窗支持复制 JSON 证据或完整 HTML，预览的布局与独立 HTML 可能不同。

v0.5.0 已在 CPR 3.18.3 安装。单账号 `gpt-6-astra / low` 鹈鹕实测到110秒未取得完整HTML，记录为 `visual_timeout`，日尝试从5增至6。三题原文与质量判定保留，不计入异常轮次。v0.5.1 缩短内置绘图任务至约1000～1500输出token，并修正全失败时的页面提示；共享模型调用改用宿主原生流，取得请求ID后在超时／解析错误时显式关闭，并在110秒总期限内预留关闭余量。仍不能保证模型在时限内完成，关闭回执也不等于宿主后台日志终态已写入。此前 v0.4.0 三题实测见下文。

v0.5.1 的短版任务在60.2秒因累计流事件超过1MiB中止，宿主日志成功收敛为 `cancelled`，并保存了请求ID。该样本没有完整HTML，不代表可视化生成通过。v0.5.2 改为逐批校验事件、只累计有界正文，以避免中间事件占满缓存。

2026-10-01，v0.5.2 在同一 CPR 3.18.3 实例对同一纳管账号请求 `gpt-6-astra / low`，64.524秒完成，宿主记录 `succeeded`，请求ID与选定账号匹配。保存的完整HTML为4,638字符／4,875字节，宿主报告输出2,076 tokens、推理181 tokens。实际CPS图像预览已渲染，HTML导出弹窗包含从DOCTYPE到闭合html的完整文档；刷新后的服务端原文读取也已验证。

本轮对照确认指纹挑战原文、输出及质量状态保持不变。用户仅授权增加一次测试预算，验收后已恢复原7次／28,672预留token配置，自动探测保持关闭；当天实际8次尝试记录保留，不重置预算。此次仍是单账号实测，不能代替多账号真实隔离与恢复验收。

## 评分器能说明什么

使用 ModelTrace 固定版本的公开参考库。每份完整输出独立提取特征并计算各候选原始分数，三份分数取平均，再统一使用 `calibration["3"]` 做 softmax。不是平均三个概率，也不是将三个单题判定投票。单题、双题评分仅供离线一致性检查，线上整轮必须三份有效输出。原始参考数据的模型标签由上游项目提供，本项目没有独立认证其后端身份。

解析规则沿用上游：保留最长合法数字序列、顺序及重复值，不补齐也不裁成要求数量；至少需要 `max(80, ceil(要求数量 × 0.55))` 个1～355范围内整数。完整传输终态独立验证：即使部分输出数字够多，只要上游未完整结束也不能评分。

对照项目 [hlwy-ai-checker](https://github.com/hanlinwenyuan/hlwy-ai-checker) 使用重复单数字采样形成分布，采样协议不同。本插件采用 [ModelTrace](https://github.com/xqy2006/ModelTrace) 三次长整数挑战，不混用其参考分布。

当前 `0.99/0.01`、每轮3题、两轮异常与两轮恢复规则尚未使用本部署的独立真值集校准。它们表达行为证据强度，不能解释成“99%证明真实模型”，也不能推导某一次业务请求必然被降级。

不使用 `x-codex-safety-buffering-faster-model`、`enabled` 或 turn-state 长度作为判定依据。探针错误、超时、工具输出、截断或解析失败的尝试不参与聚合，每轮最多尝试六次。未收齐三份有效输出、整轮过期或低分差时无法判定，不作为降级证据。已冷却账号遇到整轮无法判定时保持隔离并退避。

## 真实部署验收记录

2026-10-01 01:33–01:35（Asia/Shanghai），v0.4.0 在 CPR 3.18.3 通过扩展页对一个既有纳管账号请求 `gpt-6-astra`。4次独立请求中，316、321、305个数字的三份完整输出参与聚合；另一次要求297个、仅返回101个数字，原文保留但不参与计算。

保存的三份完整原文交由仓库固定的 ModelTrace 原版 `analyzeGlobalOutputs` 离线复算，全部16个候选概率与插件差异最大 `7.38e-18`。第一候选 `gpt-6-astra` 99.7705626%，其次 `gpt-5.6-sol` 0.2063735%、`gpt-6-sol` 0.0208862%；`gpt-5.6-luna` 约0.0000877%。本轮判定 healthy，页面读取原始挑战/输出成功，未额外发起模型请求。

此次验证的是单账号采集、持久化、三题评分及页面完整证据读取。原文和请求ID仅存部署端及本地忽略目录，不提交公开仓库。自动探针保持关闭；维护20秒限制仍存在，旧版曾因此超时。多账号真实路由、异常隔离及恢复传播仍需验证，`runtime_isolation_verified=false` 保留这一边界。

部署后的验收至少要涵盖：

1. **准入与范围**：宿主资源维护创建两组两 Key；只有配置中的原生启用 OpenAI 账号进入探测组；自有与额外业务 Key 均只绑定健康组。
2. **三题与定向调用**：确认三次挑战固定同一配置账号、出口和目标模型，互不携带上下文；三份完整输出和请求 ID 可通过单账号 `POST evidence` 读回，全账号 `GET status` 仅含摘要；只有1/3或2/3时无新归因，3/3时与固定 JavaScript 实现重新计算一致。中断后可接续，超时及预算不足不伪造结果。确认没有别名或其他路由插件改写目标模型；通过宿主 API 固定账号不等于已验证实际后端身份。
3. **隔离传播**：用可控测试池形成隔离状态，先核组成员读回，再核新业务请求不再选择该账号；已经在途的请求单独记录。
4. **恢复门槛**：冷却到期不会直接回组；完整两轮恢复证据成立并经维护同步后，才重新收到业务流量。
5. **旁路和故障**：业务 Key 多绑组时停止探针；组写入/读回失败时明确报错；重启保持已冷却状态；原生手动禁用账号不会被插件启用。
6. **消耗和全池保护**：核对宿主实际 usage/账单、日预算停止状态、探针滞后与 `pool_guard`；它不是上游输出长度或费用的硬上限。
7. **鹈鹕对比**：通过界面选定账号、模型与推理强度，确认实际调用账户、请求 ID、完整 HTML、耗时与共享预算读回；执行前后对照指纹原文和质量状态未被推进。刷新后通过 `POST visual-evidence` 读取原文，核对安全图片预览与 HTML／JSON 复制导出。

质量误报校准应使用独立、可说明来源的基线账号与数据，保持相同目标模型、推理强度和宿主路径，并按完整确认轮评估误隔离/误恢复率。不要用参与调参的样本同时声称独立验证准确率。

## 留存

`quality` 命名空间保存每账号当前或最近一轮的指纹挑战提示词、完整输出、请求 ID、解析数量和候选排序，以及最近12轮摘要、质量状态、租约和预算。开始新一轮会替换上一轮完整证据；超过30分钟的未完成轮次会失效。每份指纹输出上限16 KiB（包括 JSON 转义后的大小），过大文本拒绝评分，不截断后继续。

独立的 `visual`、`logic` 命名空间分别按账号保留最近4份鹈鹕和糖果记录，包括账号 ID、模型、推理强度、提示词、请求 ID、原始输出、时间与判定。输出及单份记录 JSON 序列化结果均受24 KiB上限约束。完整传输但文档不符合要求的回答保留原文与错误；超时、传输不完整或过大输出不保存正文。这些记录与指纹证据由宿主分别持久化。

扩展页默认加载全部账号摘要；用户按账号点击 **加载完整证据** 或 **加载完整可视化结果**，分别通过 `POST evidence`、`POST visual-evidence`、`POST logic-evidence` 读取，避免全部账号的原始文本挤入一次管理响应。`POST probe` 返回本次账号的完整轮次证据，`POST visual` / `POST logic` 返回本次记录；读取和复制导出均不发推理请求。

本仓库黄金样本全部是合成数字，不包含此前真实测试输出。宿主可能按自己的配置记录探针请求，部署时应同时核对宿主日志留存。
