# Codex Quality Guard

`codex-proxy-rs` 独立插件：对指定 OpenAI 账号执行 ModelTrace 行为探针，连续异常后移出健康组，冷却后复测通过再放回。v0.6.0 提供三题指纹、鹈鹕绘图、糖果逻辑三种测试，共用账户选择、输出卡片与结果导出。插件 ID：`jiahao6635.quality-guard`。

**一次指纹检测 = 同一账号、同一模型的三次独立挑战 + 三份有效完整输出 + 一次聚合归因。** 各答案先计算原始特征分数，再求平均，最后使用 ModelTrace 三次查询的校准参数计算候选概率。ModelTrace 分数不是后端模型身份证，也不能确认此前哪一次业务请求被替换了模型。

v0.5.2 已在 CPR 3.18.3 完成同账号鹈鹕实测：`gpt-6-astra / low` 用时64.5秒，取得4,875字节完整HTML，预览与HTML导出文本已在扩展页验证；宿主记录成功，原有三题原文及质量状态保留。

v0.4.0 已在 CPR 3.18.3 完成单账号实测：4次请求取得3份有效完整答案（316、321、305个数字），联合归因 `gpt-6-astra` 99.77056%，与 ModelTrace 原版 JavaScript 复算一致。该结果验证采集、保存、聚合和页面展示流程，不等于身份真实性或检测准确率验证；详见 [验证说明](docs/validation.md)。

## 分组方式

| 资源 | 成员 / 用途 |
| --- | --- |
| 插件自有探测组 | 配置中纳管、原生启用且属于 OpenAI 的账号；包含质量冷却账号 |
| 插件自有健康组 | 通过准入的账号；连续异常后移出，恢复通过后加入 |
| 插件自有探针 Key | 只绑定探测组，供插件固定账号推理；不得提供给业务客户端 |
| 插件自有业务 Key | 只绑定健康组，供业务使用 |

插件由宿主自动维护入口创建这些资源并同步成员。它不改账号原生 `enabled`，原生禁用账号不会被探针重新启用。停止插件或定时器也不会自动恢复已隔离账号。

一个实例的自动质量判定针对一个配置 `model`，健康组按账号控制访问。鹈鹕和糖果模式可选择其他受支持模型，默认 `gpt-6-astra / medium`；独立保存测试判定，不改变自动冷却的质量判定目标。一个模型通过检测不代表同账号的其他模型也已验证。业务 Key 若还绑定其他组，就可能绕过健康组；所有实际业务入口都必须只访问健康组。

从 0.1.0 升级到 0.1.1 或更高版本时，先删除旧配置中的 `provider` 字段；已有探测状态可直接读取，冷却与恢复进度保留。

## CPR 3.18.3 实机入口限制

实机已确认：**独立宿主 CLI 未绑定内部 HTTP 分派端口，因此本版 `status` / `tick` CLI 不可用于实际运行，systemd 模板也不能绕过这个限制。** 协议测试不代表宿主 CLI 集成已通过。请使用运行中服务的管理路由 `GET status` / `POST probe`，或配置 `auto_probe: true` 由宿主维护周期触发。自动单题20秒；管理调用可使用更长的父调用期限。不要按 CLI 报错推断后台维护也失败。

## 安装与首次启用

### 1. 准备兼容宿主与插件包

Linux x86_64 可直接在宿主“插件管理 → 安装 → GitHub”填写 `jiahao6635/codex-quality-guard`，选择已发布的稳定版本。预算校验需要 `v0.1.3` 或更高版本；旧版“插件管理路由声明无效或重复”的问题已在 `v0.1.2` 修复。

- 宿主：`codex-proxy-rs >=3.18.0, <3.19.0`，支持当前进程插件合同。
- SDK 固定为提交 `718b959fc137ad7f0d1965abe1f960a978971921`；宿主、SDK、打包 CLI 须保持合同兼容。
- 本地构建需要 Rust **1.97**、Node.js **22**、Python 3、Bash 和目标平台编译工具。

在目标平台构建，例如 Linux x86_64：

```sh
cargo test --manifest-path backend/Cargo.toml --locked
node scripts/verify-scorer.mjs
bash scripts/package.sh x86_64-unknown-linux-gnu
ls dist/*.tar.gz dist/*.sha256
```

打包脚本安装与 SDK 同提交的 `cpr-plugin` 到项目 `.cache/`，生成宿主可安装的包和摘要。其他支持目标为 `aarch64-unknown-linux-gnu`、`aarch64-apple-darwin`；跨平台构建需自行准备目标工具链和链接器。

也可在仓库 **Actions → CI** 成功运行后下载 `codex-quality-guard-linux-x86_64` artifact，解压后取得其中的 `tar.gz` 和 `sha256`。这是 CI 制品，不等同于已发布的 GitHub Release。

### 2. 安装并让宿主准备资源

在宿主“插件管理”上传 `tar.gz`，按宿主流程接受可信制品。**v0.2.0 使用 CPR 3.18 的协议 v2 和全信任进程模式，不兼容 CPR 3.17。** 旧版本必须重新构建，不能仅修改版本范围。

插件通过宿主模型接口指定账号，通过自有资源接口维护两组两 Key。CPR 3.18 的基础账号事实没有填充分组，因此补用 SDK 内部 HTTP 分派读取公开管理员账号列表（支持分页），不读取账号凭据、不直接连接数据库。读取失败就停止本次操作，不把缺失数据当作空成员。插件仅查询探针 Key 预算，不修改或重置预算。

保持插件配置的 **`enabled: false`**。宿主实例需处于启用状态，才能运行维护和命令；这是两个不同开关。维护会创建分组与 Key，但此时 `tick` 不发推理，且不开始账号成员同步。

进入 **插件 → 扩展页 → 账号质量探针** 查看资源维护状态。若提示未就绪，检查实例是否启用、维护错误和宿主日志，等待维护完成；刷新结果本身不会创建资源。

### 3. 配置账号与业务访问范围

以 [config.example.json](config.example.json) 为模板，在宿主插件设置中填写：

1. `account_ids`：实际账号 ID，最多100个；插件固定使用 OpenAI。
2. `model`：实际用于质量检测的模型，默认 `gpt-6-astra`。确认此模型没有经其他插件或网关别名规则改写；指定账号不代表绕过宿主模型路由。
3. 业务客户端使用自有业务 Key，或将现有业务 Key **仅绑定到 status 返回的健康组**，并把这些现有 Key 的 ID 填入 `business_key_ids`。该列表用于范围校验，不自动修改已有 Key 的分组。
4. 检查探针 Key 的日、周美元预算。字段使用十进制字符串，如 `"5"`、`"25"`。自有 Key 创建后，插件不覆盖管理员修改过的预算，只验证它们为正数且不宽于配置值。下调配置时也要在宿主 Key 管理中同步收紧已有 Key，否则探针停止并报告预算错误。
5. 将配置 `enabled` 改为 `true` 并保存。等待维护将纳管账号加入探测组；未经过准入的账号不进入健康组。

在 `status` 中确认 `key_scopes_ok: true`、`probe_budget_ok: true`、`maintenance.ok: true`、账号范围正确。探针 Key 永不外用；插件 status 只包含资源 ID，不回显密钥。未纳入校验的其他业务 Key 仍由部署者确保不存在旁路。

### 4. 在扩展页完成三题指纹检测

进入 **插件 → 扩展页 → 账号质量探针**，先选择检测账号，核对顶部邮箱、名称与完整账号 ID，再选择 **ModelTrace 三题指纹** 并点击 **开始三题检测**。页面串行调用三次独立挑战，不携带前题上下文；每道题最多等待110秒，并受宿主管理调用剩余期限约束。保持页面打开，直到出现本轮判定和候选模型排序。

- 每份完整输出单独解析；收到三份有效答案后才计算一个模型指纹。只有1/3或2/3份有效输出时，不显示新的归因结果，也不计入准入、异常或恢复轮次。
- 每轮最多六次尝试。超时、错误或不符合解析要求的答案不会替代有效答案；六次仍不足三份，整轮记为无法判定。**失败也消耗尝试次数和预算。**
- 页面默认读取全部账号的摘要，点击 **加载完整证据** 后，输出卡片展示完整模型文本，并可展开提示词、请求 ID、要求数字数量与实际解析数量。此操作只读证据，不发模型请求；刷新页面后需重新加载。最终结果展示全部候选模型概率和预期模型概率。
- **本题结束后停止** 会等待当前请求完成、保存结果，再停止后续调用。页面关闭、网络中断或日预算用完时，已保存的输出保留。在本轮开始后的30分钟内可刷新并点 **继续本轮三题**；从开始起超过30分钟就失效，不能将相隔很久的答案拼成一次检测。先核对租约和执行状态，避免重复发起。
- 日预算至少需要容纳三次有效调用；建议预留六次尝试以容纳失败。`max_daily_output_tokens` 也要覆盖相应尝试的 `max_output_tokens` 预留量。插件不会绕过或重置预算。

管理员管理路由包括 `GET status`、`POST evidence`、`POST probe`。`GET status` 返回全部账号摘要，不携带原始提示词和输出；`POST evidence` 正文为 `{"account_id":"acct_实际账号ID"}`，只返回指定账号的完整证据，避免多账号响应超出宿主上限。`POST probe` 正文是 `{"account_id":"acct_实际账号ID"}`，**一次只执行一道题**：返回 `challenge_recorded` 表示本轮尚未完成，`batch_completed` 表示已产生本轮结果。扩展页负责串行继续；各账号独立保存本轮证据，不能混用。未纳管账号会被拒绝，尚未到期返回 `no_due_account`。不需要为每个账号创建单独的组。

**自动探测通过 `auto_probe: true` 开启，默认关闭。** 宿主每次维护先同步成员，再对一个到期账号执行一道题，接续同一账号的未完成轮次；全部账号共用日预算。宿主通常每次维护结束后等待30秒。自动单题最多20秒，还受维护剩余期限限制；慢响应可能持续无法判定。此时可关闭自动探测，在扩展页手动完成三题。超时不能说明模型降级。启用自动模式前停止已有外部定时器，避免重复调度。

完整一轮的正常结果满足首次准入条件；分组变更由后续宿主维护同步，与记录结果不是同一事务。结果卡片显示行为判定和账号状态，不把一次调用成功当作准入成功。

### 5. 绘图与糖果逻辑测试

选择账号后切换到 **鹈鹕可视化测试** 或 **糖果逻辑测试**。两项默认 `gpt-6-astra / medium`，支持选择模型、推理强度和1～4份串行输出；每份最多110秒。每次固定所选账号 ID，界面可选模型不代表该账号一定有上游权限。

鹈鹕提示词按以下原文发送，不追加输出要求：

> 创建一个HTML，内容是SVG绘制一个鹈鹕骑自行车的2D动画，你不需要任何测试

收到完整 HTML 后，查看预览与源码，再点击绘图正常／异常的人工判定按钮。异常标记为 **未通过／疑似降智**。预览不执行 JavaScript，若动画依赖脚本，请导出完整 HTML 后复核，不能仅因预览静止判为异常。

糖果题按以下原文发送：

> 在一个黑色的袋子里放有三种口味的糖果，每种糖果有两种不同的形状（圆形和五角星形，不同的形状靠手感可以分辨）。现已知不同口味的糖和不同形状的数量统计如下表。参赛者需要在活动前决定摸出的糖果数目，那么，最少取出多少个糖果才能保证手中同时拥有不同形状的苹果味和桃子味的糖？（同时手中有圆形苹果味匹配五角星桃子味糖果，或者有圆形桃子味匹配五角星苹果味糖果都满足要求） 苹果味 桃子味 西瓜味 圆形 7 9 8 五角星形 7 6 4

糖果题自动提取明确最终答案：**21 通过，其他数值未通过／疑似降智**。21 的策略是凭手感取9颗圆形和12颗五角星。仅在正文中出现21不会通过；没有明确结论或结论冲突时为无法判定。超时、请求失败和不完整输出也为无法判定。

每份记录包含账号 ID、模型、推理强度、完整提示词与输出、耗时、请求 ID和判定。加载完整结果只读取证据，不发请求。两项测试独立于 ModelTrace 指纹轮次和自动冷却／恢复；`auto_probe` 仍只调度 ModelTrace。它们共用日尝试数、输出预留和探针 Key 预算，失败也消耗额度，同一账号已有请求时拒绝重叠执行。

| 管理路由 | 正文 / 结果 |
| --- | --- |
| `POST visual` / `POST logic` | `{"account_id":"acct_实际账号ID","model":"gpt-6-astra","reasoning_effort":"medium"}`；一次一份，分别返回 `visual_recorded` / `logic_recorded` 及样本 |
| `POST visual-evidence` / `POST logic-evidence` | `{"account_id":"acct_实际账号ID"}`；分别返回该账号最近4份原始记录 |
| `POST visual-review` | `{"account_id":"acct_实际账号ID","sample_id":"实际样本ID","verdict":"pass"}`；`verdict` 为 `pass` 或 `fail`，只保存已完成样本的人工判定，不调用模型、不扣额度 |
| `GET status` | 返回全部账号的摘要，不携带原始提示词与输出 |

### 6. 预览与导出

CPS 扩展页限制子 iframe 和直接下载。插件使用`data:image/svg+xml` 图像预览模型 HTML／内联 SVG／CSS，不执行生成的 JavaScript，也不加载外部资源。复杂布局可能与独立 HTML 页面不同，完整源码始终保留。

点击单项 **导出**／**导出 JSON** 或底部 **导出全部结果**，在弹窗选择 **复制全部内容**，按显示的文件名保存为 JSON；其中包含账号 ID、提示词、完整输出与请求信息。需要独立 HTML 时点击可视化卡片的 **导出 HTML**，复制后保存为 `.html`。复制权限受限时可在已选中文本上按 `Ctrl+C`／`⌘C`；导出不发模型请求。

## 默认判定与恢复

| 阶段 | 默认规则 |
| --- | --- |
| 单份有效答案 | 必须取得完整成功文本，无工具/上游错误；按 ModelTrace 解析最长数字序列，范围1～355，至少 `max(80, ceil(要求数量 × 0.55))` 个；不截断、不补齐 |
| 一轮指纹 | 同一账号、同一模型的3份独立有效答案；按原始特征分数求平均后使用 `calibration["3"]` 计算概率 |
| 正常 | 第一候选等于请求模型，库内分数 ≥0.99 |
| 异常 | 第一候选不同，分数 ≥0.99，预期模型分数 ≤0.01 |
| 无法判定 | 六次尝试未收齐三份有效输出、轮次过期或聚合分数不足；不计异常、不据此恢复 |
| 首次准入 | 一轮三题聚合结果正常 |
| 异常隔离 | 同一替代候选连续2轮聚合结果异常；两轮间隔至少5分钟 |
| 冷却 | 初始1小时；到期只允许恢复探测，不按时间直接放行 |
| 恢复 | 连续2轮三题聚合结果正常；两轮间隔至少10分钟 |
| 恢复失败 | 异常或无法判定均保持隔离，冷却退避至2、4、最多6小时 |
| 正常巡检 | 正常一轮结束后30分钟再次到期；实际执行还受队列与预算限制 |

每道题不再单独投票判定正常或异常；同一轮只产生一次聚合判定。轮次之间的候选改变、无法判定会打断连续异常或恢复证据。配置字段 `samples_per_round` 为兼容旧配置保留，固定为3；不表示在三题聚合后再重复三轮。阈值是保守运行策略，未经过当前部署环境独立误报校准。

### 全池保护

当曾通过准入的纳管账号数大于1，且其中 `cooling/recovering` 比例**超过** `max_quarantined_percent`（默认50）时，维护暂停继续将这些账号从健康组移出，并在 `maintenance.pool_guard` 标记异常。已经被移出的账号不会因此加回。它保留现有可用容量，也意味着部分已判异常账号可能暂留健康组，应及时检查指纹漂移或上游整体变化。

单账号池仍会正常隔离。设为100可关闭这个比例保护；此时全部账号都有可能被移出健康组。

## 消耗、状态与边界

- ModelTrace 每次使用新挑战，固定 `reasoning.effort=low`；鹈鹕和糖果使用所选推理强度，默认 `medium`。三种测试均默认 `max_output_tokens=4096`，不携带业务上下文或旧 turn-state。
- 默认全插件每天最多100次尝试，预留输出总额409600 tokens；按 **UTC 日期**计数。发起前预留整份上限，失败也不退款。它们是插件发起预算，上游可能忽略输出参数，不能保证真实费用硬上限；宿主 Key 预算是额外约束。
- 多账号共用串行探针与日预算。额度耗尽会形成监测空窗，`overdue_ms` 可用于观察滞后；探针通过不保证下一次业务请求仍使用相同模型。
- 修改目标模型、评分阈值或判定策略会要求重新准入；已有冷却保留恢复门槛与租约。批量修改可能暂时移空健康组，应在受控入口验证。
- 从纳管配置移除的账号会退出两组，旧状态在租约结束后清理；重新纳管须重新准入。
- `quality` 状态命名空间按账号保存当前或最近一轮的完整指纹提示词、输出、请求 ID、实际解析数量与候选排序，以及最近12轮证据摘要；开始新一轮后替换上一轮完整输出。指纹文本按16 KiB（包含 JSON 转义后的大小）上限接收，过大输出拒绝评分，不截断后冒充完整。
- 鹈鹕与糖果记录分别使用 `visual`、`logic` 命名空间，每种每账号保留最近4份；完整输出及单份记录的 JSON 序列化结果均受24 KiB上限约束，过大内容记录错误且不保存正文。三类状态由宿主持久化，原始业务请求不进入这些记录；宿主日志与留存策略独立。
- **插件 → 扩展页 → 账号质量探针** 展示账户身份、三题进度、完整证据、候选排序、冷却状态、鹈鹕人工判定和糖果自动判分。页面通过宿主桥访问已注册管理接口，不读取密钥；打开页面只读取结果，不自动发起推理。
- `maintenance.membership=database_readback_only`、`runtime_isolation_verified=false` 明示当前只有组成员数据库读回。变更传播到调度缓存、业务 Key 真正不再选到隔离账号，需要实际网关验收；已开始的请求不会被撤回。
- 配置 `enabled=false` 暂停探针和成员同步；停用宿主实例停止维护；关闭 `auto_probe` 仅停止自动探测；停止 timer 仅停止外部 tick。自有资源和现有成员保留，撤销业务访问应在宿主 Key 管理中处理。

## 参考项目与算法边界

- [ModelTrace](https://github.com/xqy2006/ModelTrace)：本插件使用其三次独立长整数挑战、参考库、逐答案特征评分、原始分数平均和三次查询校准。完整输出会保存并用于解析；并非要求输出数字数量与提示词完全相等。
- [hlwy-ai-checker](https://github.com/hanlinwenyuan/hlwy-ai-checker)：采用多次单整数回答的分布指纹；其采样协议与 ModelTrace 的三份长整数序列不同。本插件没有混合两套协议或将两者概率相乘。
- [Sub2API IQTestModal](https://github.com/ranxi2001/sub2api/blob/2d55b424e3cac42814e81c9fec700595985faafb/frontend/src/components/admin/account/IQTestModal.vue)：参考其明确账号、分项输出、原文查看及导出交互；本插件以现有原生页面自行实现，没有复制该仓库代码。

候选概率是在固定参考库内的相对归因，未收录的新模型也可能被归到最相似的已有候选。`faster-model` 等响应头不参与本插件的模型指纹计算。
